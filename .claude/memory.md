### 2026-05-14 - W1 users + JWT cookie + CSRF + roles

- Summary: shipped W1 of the plan. Schema: `migrations/000011_create_users` adds `users` (id text, email text unique, password_hash, role check admin|operator|viewer, is_active, timestamps, last_login_at) and `refresh_tokens` (id, user_id FK CASCADE, token_hash unique, family_id, expires_at, revoked_at, replaced_by self-ref, indexes on user, family, expiry). New sqlc queries `users.sql` and `refresh_tokens.sql`; `sqlc generate` regenerated. Domain: `internal/core/domain/user.go` exposes `User`, `RefreshToken`, `Role` (admin|operator|viewer with `IsValidRole`) + sentinels (`ErrUserNotFound`, `ErrInvalidCredentials`, `ErrInvalidUser`, `ErrUserAlreadyExists`, `ErrInvalidRefreshToken`). Crypto primitives in `internal/platform/crypto`: `passwords.go` wraps bcrypt (cost 12 default, `ErrPasswordMismatch`); `jwt.go` exposes `JWTSigner`/`JWTClaims`/`NewJWTSigner` enforcing 32-byte HS256 secret, issuer verification and expiry, collapsing all parse failures into `ErrInvalidJWT`. Ports: `internal/core/ports/user.go::UserRepository`/`RefreshTokenRepository`. Repositories: `postgres/user_repository.go` (sqlc-backed, unique-violation → `ErrUserAlreadyExists`) and `postgres/refresh_token_repository.go` (returns revoked tokens for reuse detection); in-memory equivalents under `inmemory/`. Use cases: `usecase/auth.go` provides `Login`, `Refresh` (family rotation + reuse-detection that revokes the whole family), `Logout`, `Me`, `UpdateProfile` and `ChangePassword` (revokes all refresh tokens on password change); `usecase/user.go` is the admin CRUD with role validation, `SetActive` and `Delete` revoking refresh tokens. HTTP: `auth_middleware.go` rewritten to accept JWT cookie first then API key, exposes `AuthPrincipal{Source, KeyID, UserID, Name, Scope, Role}` and `EffectiveRole()` mapping admin scope → admin role; `RequireRole` replaces the ad-hoc `RequireAdminScope` (kept as wrapper). New `csrf_middleware.go` enforces double-submit `X-CSRF-Token` only for user sessions on unsafe methods (constant-time compare). New `auth_handlers.go` exposes `POST /v1/auth/login`, `/v1/auth/logout`, `/v1/auth/refresh`, `GET/PATCH /v1/me`, `POST /v1/me/password` and admin user CRUD under `/v1/admin/users` (List/Create/Get/Update/Delete). Cookies issued at login: `oai_session` (HttpOnly, Secure-from-config, Path=/), `oai_refresh` (HttpOnly, Secure, Path=/v1/auth), `oai_csrf` (JS-readable, Secure). Router wraps every route with role guards: GETs require viewer+, POST analyses/chat require operator+, /v1/admin/* requires admin. Config: new `JWTConfig` (secret, issuer, access/refresh TTLs) and `CookieConfig` (domain, secure); `OBSERVAI_JWT_SECRET` joins `OBSERVAI_ENCRYPTION_KEY` as required for non-local modes with a length check (≥32 bytes). cmd/observai-api wires `JWTSigner`, `usecase.Auth`, `usecase.User` and the new user/refresh repositories, refusing to start in non-local mode if any of them is missing.
- Decisions: kept refresh tokens as opaque random hex stored hashed (SHA-256) instead of JWTs because rotation + reuse-detection requires DB-side revocation tracking — JWT-only refresh would leak rotation state. Refresh-token reuse triggers `RevokeFamily` (kills every sibling token) so a stolen-then-rotated token cannot keep generating sessions; logout only revokes the supplied token so a user with multiple devices keeps their other sessions. Static admin/default API keys still work; `EffectiveRole` maps the legacy admin scope to admin role so existing static keys continue to satisfy `RequireRole(domain.RoleAdmin)`. When the middleware is fully disabled (local mode without any credentials configured) it injects a synthetic admin principal so role guards remain uniform without a special-case for tests — production runs validate that auth is configured, so the injection path cannot fire there. Public endpoints (`/v1/auth/login`, `/v1/auth/refresh`, `/v1/openapi.yaml`, operational probes) are added to the default skip list so unauthenticated clients can use them. Imported `internal/platform/crypto` from `internal/core/usecase/auth.go`: rules forbid SDK/framework/db imports in core, but `platform/crypto` is stdlib-only project code so the import respects the spirit of the rule and avoids a port/adapter indirection for primitives that have no swap candidate. Chose `Sessions *usecase.Auth` (not `Auth`) in `RouterOptions` to avoid colliding with the pre-existing `Auth AuthConfig` field. Cookie SameSite defaults to Lax; operators set `OBSERVAI_AUTH_COOKIE_SECURE=true` in prod (Validate does not force this yet — added to W8 hardening list). CSRF token rotates per access-token issue (login + refresh) so an SPA must re-read the cookie on refresh; the value is returned in the response body so JS does not have to read the cookie until the next refresh.
- Pending: run `migrate up` (or `OBSERVAI_MIGRATE_ON_START=true`) to apply migration 000011 in any running environment. Audit-event integration for `auth.login`/`auth.logout`/`auth.login_failed`/`user.created`/`user.updated`/`user.deleted` is currently only via the HTTP audit middleware (per-request row); the per-domain-event recorder is W8. Forcing `OBSERVAI_AUTH_COOKIE_SECURE=true` in prod is on the W8 hardening list. Postgres integration tests for the new user/refresh-token repositories require `OBSERVAI_TEST_DATABASE_DSN` and were not added in this wave.
